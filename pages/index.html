XCP-HL yum repository: xoa-hl

Signed RPM repository for XOA-HL, Xen Orchestra HomeLab Edition. Built for AlmaLinux 9.

XOA-HL is a self-hosted Xen Orchestra appliance VM. This site serves a yum-resolvable repository containing recent released builds of the xoa-hl package, so an installed XOA-HL appliance can update itself in place instead of reinstalling from scratch.

On a running appliance, /etc/yum.repos.d/xoa-hl.repo already ships pre-installed: the xoa-hl RPM writes it directly in its %post script. The copy published here exists for reference and as a manual bootstrap if that file is ever missing.

Add the repository

On an XOA-HL appliance, as root:

curl -o /etc/yum.repos.d/xoa-hl.repo \
  https://vagrantin.github.io/xoa-hl/xoa-hl.repo

rpm --import https://vagrantin.github.io/xoa-hl/xcp-ng-ce-public.asc

yum clean all
yum check-update xoa-hl

Update

yum update xoa-hl

A handful of recent releases are kept, so you can list what is available and roll back within that window:

yum --showduplicates list xoa-hl
yum downgrade xoa-hl-<version>

Verification

The repository metadata (repodata/repomd.xml) carries a detached armored signature from the XCP-ng Community Edition signing subkey, and repo_gpgcheck=1 in the .repo file above verifies it on every run. Because the signed repomd.xml records a SHA-256 of primary.xml, which in turn records a SHA-256 of every package, that one signature covers the integrity of everything you download.

Per-package signature checking is off (gpgcheck=0), and that is deliberate. The RPMs are signed by a GPG signing subkey, and some environments only register the primary key on import, which then reports NOKEY for a subkey-made signature. This is the same trust model apt uses: the release file is signed, individual packages are not.
